# 双语本地 Markdown 图谱增强 RAG 设计补充

## 意图与范围

本文件补充 `docs/图谱增强RAG项目设计草案.md`。项目仍以图谱增强的多跳检索为研究主线，以纯向量检索和无权一跳检索为公平对照。第一版语料从《动手学深度学习》中文仓库 `d2l-ai/d2l-zh` 与英文仓库 `d2l-ai/d2l-en` 下载对应主题的 Markdown 文件，在本地完成解析、分片、向量化、索引、图谱构建、召回与重排。回答生成可使用外接大模型 API。

中文问题允许召回两种语言的原文证据；默认输出中文答案，引用保留原文语言与来源。第一版主题仍为序列模型、注意力机制与 Transformer。具体文件由显式来源清单选定，不仅凭章节编号推断中英文文件对应关系。

## 已比较的方案

1. **统一双语索引（选定）**：所有片段使用同一个多语言 embedding 模型建立本地向量索引，记录语言元数据；三路检索都在同一候选池工作。实现和公平对照较简单，中文问题可直接得到英文证据。风险是英文与中文的近似重复内容占用 Top-k，需要在上下文选择时限制同主题冗余。
2. **分语言索引后融合**：中文、英文各自检索，再合并归一化分数。可以精确控制各语言配额，但分数融合和配额会增加额外调参，容易影响第一版对照公平性。

两个方案都通过本地 Markdown 清单下载文件。第一版选统一索引；如果开发集显示严重的语言偏置，再将分语言融合列为后续消融，不在测试集上临时改策略。

## 数据获取与出处

- 来源清单逐项列出仓库、完整 Git 提交 SHA、相对文件路径、语言、显示标题、文件 SHA256 与上游许可备注。中文和英文仓库分别固定版本，不假定两个提交严格同步。
- 下载命令只获取清单中的 Markdown 文件，保存到 `data/raw/d2l-zh/` 与 `data/raw/d2l-en/`。下载后校验文件 SHA256；失败时停止构建，不静默使用旧缓存。已有本地文件在校验通过时可复用，支持离线重建。
- 版本、文件哈希与入库参数写入本地构建清单。每个片段保留仓库、提交、相对路径、标题层级、语言、原文位置以及可点击的 GitHub 固定版本链接。
- 排除仓库中的 `*_origin.md` 等翻译原稿副本，防止重复入库；实际纳入的文件由来源清单决定。对目录名不同或章节边界不同的中英文内容不做自动一一对齐。
- 本地原始教材文件、缓存、向量索引和图索引均不提交到项目公开仓库。公开仓库只提交来源清单、下载和构建脚本、自写样例及复现说明。正式发布前核对两个指定提交下的正文许可与署名要求；项目代码的 MIT 许可不覆盖教材正文。
- 保留用户自写 Markdown 来源适配器：添加文档只修改来源清单并重建索引，不修改检索算法。

## 本地处理与检索

1. Markdown 解析器识别标题层级、段落、列表、公式与代码块；分片优先遵循小节边界，超长小节再按固定 token 上限切分，保留少量重叠。原文中的构建指令、导航与重复翻译原稿不作为知识片段。
2. 片段 ID 由来源标识、仓库内路径、小节锚点和规范化文本哈希构成，与导入顺序无关。新增英文或中文文件后，未改变的旧片段 ID 不变。不同语言的片段始终有不同 ID。
3. 同一个本地多语言 embedding 模型对中文问题及中英文片段编码；模型 ID 与版本、归一化方式记录在运行配置。向量索引本地持久化。
4. 图谱边仍必须指向真实片段 ID。概念可记录中英文别名，但跨语言别名合并需要可检查的规则或人工核查；不能因翻译相似就把两条来源合并成同一证据。
5. `dense`、`one_hop`、`typed_path` 三种方案共用语料、分片、embedding、生成模型、提示词和最终 token 预算。检索和重排在本地执行；各模式返回统一的证据对象。上下文选择按片段 ID 去重，并控制同主题的双语冗余，保留原始引用。
6. 生成端使用可替换的客户端接口。可接 DeepSeek 或其他兼容 API；模型不负责检索或重排。提示词要求依据给定片段用中文回答、逐项引用片段 ID，并在证据不足时明确拒答。调用前校验引用只指向实际提供的片段。

## 评测与验收

- 原计划的 12 道开发题、36 道封存测试题和三个检索方案保持不变。双语语料入库后重新人工核查题目与金标准证据；每个必需证据组可列出人工确认能证明同一论点的中英文候选片段 ID，命中任一即可。避免英文新证据改变“不可回答题”的边界。
- 每题记录检索片段 ID、语言、原文路径、答案、引用、延迟与 API 用量。可以按题型和证据语言拆分结果，但主对照仍在同一 36 题上进行。
- 验收覆盖：两个上游仓库各有可校验的本地 Markdown 文件；中文问题能命中英文证据并生成中文答案；重复构建结果稳定；新增自写 Markdown 后旧引用保持有效；离线索引重建不访问大模型；无证据问题拒答。
- 测试使用自写双语 fixture 与假 embedding/假生成客户端，不下载或提交真实教材正文，也不读取真实 API 密钥。真实模型和 API 的冒烟测试单独执行。

## 待实施时决定

- 依据本地 GPU 显存选择多语言 embedding 模型；优先验证 BGE-M3，显存不足时采用较小模型，并将实际模型固定于实验配置。
- 依据上游两个仓库的实际目录与许可，确定来源清单中的文件路径和提交 SHA。选择后不得在封存测试过程中更换来源版本。
