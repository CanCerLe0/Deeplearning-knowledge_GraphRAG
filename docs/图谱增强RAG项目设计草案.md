# 图谱增强的深度学习知识问答：项目设计稿

## 目标与定位

面向人工智能算法实习岗位，用 1–2 周完成一个可演示、可复现的 RAG 算法项目，最终发布到项目作者自己的 GitHub 公开仓库。项目研究问题是：在深度学习概念间的跨章节、多跳问答中，带关系类型与来源约束的图谱检索，是否优于相同语料、相同生成模型、相同上下文预算下的纯向量检索？

用户原始设想是机器学习/深度学习知识库、知识图谱展示、RAG 问答。第一版将领域缩为“序列模型、注意力机制与 Transformer”，从《动手学深度学习》的中文仓库 `d2l-ai/d2l-zh` 和英文仓库 `d2l-ai/d2l-en` 下载对应主题的 Markdown 作为本地语料；中文第 9、10 章的相关小节是选材起点，英文文件按主题逐项对应，不仅凭章节编号匹配。第 14.8 节 BERT 仅作为时间允许时的扩展。展示界面仍保留未来扩展到完整机器学习/深度学习知识库的接口与说明，但不声称第一版已经覆盖全部领域。

## 成功标准

1. 系统输入中文问题，可同时召回中英文原文片段，以中文输出答案、标明原文语言的可点击引用、检索到的证据片段及实际使用的概念路径。
2. 建立至少三个严格可比的检索方案：向量 Top-k；向量种子加无权一跳扩展；提出的关系感知、最多两跳的路径重排方法。生成模型、提示词、上下文 token 上限保持一致。
3. 当前规模为 72 道题：12 道开发题、60 道已审核的测试题，包括单概念题、跨概念/多跳题、比较题、语料内不可回答题。每题保留标准答案、题型和必需证据组；每组列出人工核查过、能够证明同一论点的中英文候选片段 ID，检索命中其中一个即可。第一周先完成 12 道开发题并在其上做功能性初评；测试题完成逐题核查和参数冻结后才作为封存集运行。
4. 报告 Recall@5、跨证据完整召回率、答案正确率、引用准确率、延迟与 API 成本。主结果按题型拆分；负面结果也照实报告和分析。样本规模只支持项目内的方向性结论，不宣称统计显著或泛化到全部机器学习知识。
5. 公开可复现代码、固定配置、语料来源与许可说明、数据构建方法、实验脚本、结果图表、演示视频或截图、README 和面试讲述要点。
6. 新增一份本地 Markdown 知识文档时，只需登记来源并重建索引，不改问答或检索算法代码；新文档出现在检索结果中，旧文档引用仍可定位。以一个小型自写示例文档验证此流程。

## 非目标与失败标准

- 第一版不微调或从头训练问答大模型；RAG 是检索增强生成，模型微调另列扩展实验。
- 不追求全量机器学习知识覆盖、复杂图数据库部署、通用 Agent 工作流或高复杂度前端。
- 第一版支持全量确定性重建索引；不承诺大规模知识库的增量更新或实时同步，但数据模型为未来扩展保留稳定 ID 和版本字段。
- 图谱不能只作为装饰；若查询时未使用图结构，则项目不达标。
- 不用不同生成模型或不同上下文长度制造表面提升；不以自动评估分数替代人工核查。

## 已比较路线

- 图谱构建质量优化：实体抽取与消歧有算法空间，但两周内难以验证问答收益。
- **图谱增强多跳检索（用户已选）**：自身实现关系感知路径打分，能建立清楚的假设、基线、消融与错误分析。
- 问题自适应检索：需同时调试问题分类与检索策略，工作量超过第一版范围。

## 数据与图谱

第一版语料为上述两个仓库中与序列模型、注意力机制和 Transformer 对应的 Markdown 文件。来源清单逐项记录仓库、完整提交 SHA、相对路径、语言、标题、文件 SHA256 和许可备注；两个仓库分别固定版本，不假定内容完全同步。下载程序只获取清单中的文件，保存到本地 `data/raw/d2l-zh/` 与 `data/raw/d2l-en/`，校验哈希后可离线重建；哈希不符时停止构建。排除 `*_origin.md` 等翻译原稿副本，且不自动把中英文小节视为一一对应。

以 Markdown 标题/小节为结构切分，超长小节再按固定 token 上限切分并保留少量重叠；解析时识别段落、列表、公式与代码块，去除构建指令等非知识正文。每个片段保留语言、仓库、提交、文件路径、标题层级、原文位置、chunk ID 和固定版本的可点击 GitHub 链接。图节点为概念；概念关系为 `prerequisite_of`、`component_of`、`contrasts_with`、`used_in`，每条边通过证据片段 ID 关联原文，并记录抽取置信度与人工抽查结果。可配置外接大模型用于候选实体/关系抽取，输出本地校验的结构化 JSON。中英文概念别名只按可核查规则或人工校验合并，不能把翻译相似片段合并为同一证据。每条边必须能追溯到原文片段；两周版随机抽查至少 40 条边并记录 precision，若质量不足则修正抽取规则并重建。图可存为本地 JSON/NetworkX；无需 Neo4j。

来源清单同时支持固定版本的 GitHub Markdown 与用户自写的本地 Markdown，均转换成同一 `Document → Section → Chunk` 结构。下载与入库分成两个步骤：已有文件校验通过时可离线重新分片和构建索引。文档 ID 由稳定来源标识生成，片段 ID 包含仓库内路径、小节锚点和规范化文本哈希，与导入顺序无关；不同语言保留不同片段 ID。新增文件后未改变的旧片段 ID 和引用链接不变。关系边始终指向可追溯的片段。索引构建与问答接口分开，增加新章节、新语言文件或自写文档只改来源清单并重建索引，不改检索算法。第一版采用全量重建，记录来源哈希、构建配置与时间；未来可按文档校验值加入增量更新。

## 算法与系统

本地 GPU 运行多语言 embedding 模型（优先验证 BGE-M3，显存不足时选较小的多语言模型），对中文问题和中英文片段使用同一编码器，在本地建立统一双语向量索引。所有方案共用该索引、语料与分片。召回、图扩展、路径评分和重排均在本地执行；外接大模型（如 DeepSeek 兼容 API）仅承担关系候选抽取与基于给定证据的答案生成。API 密钥由环境变量提供，不写入仓库；实际模型标识、版本和生成参数作为运行配置记录。

对问题提取概念种子与关系意图。向量检索获得 Top-k 种子片段，再关联到概念节点。候选证据为种子片段及图上最多两跳可达概念对应的原文片段。提出的方法给候选片段打分：

`S = α·向量相似度 + β·最佳可信路径分 + γ·问题概念覆盖度`。

路径分由边置信度、关系类型匹配、跳数惩罚组成。用开发集调 `α, β, γ`，固定后在测试集一次评估。选择证据时按片段 ID 去重，限制同一章节及同主题双语冗余，并控制三个方案相同的总 token 预算；不得让近似翻译片段占满上下文。若图路径无可信原文证据，退回向量检索结果；回答只能引用实际提供的原文片段并标明语言，不能把图边本身当成事实来源。比较任务可测试去掉关系类型权重、去掉路径项的消融。

流程：固定版本下载中英文 Markdown 并校验 → 本地解析与分块 → 本地向量化及统一索引 → 关系抽取/消歧 → 带来源的概念图 → 中文问题向量检索及概念种子 → 本地图扩展/重排 → 中英文原文证据 → 外接大模型生成中文带引用答案 → 图与引用可视化。

## 评测设计

当前题集 72 题：18 道单概念、30 道多跳、12 道比较、12 道不可回答；开发 12 道、测试 60 道，按题型分层。2026-11-25 将 24 道备选题全部并入原 36 道测试题。第一周仅完成开发题核查；第二周补齐并封存测试题后，固定算法与参数，再运行测试。原方案要求至少 36 道题由作者依据原文自行撰写；本轮评测取消该配额。测试题由助手起草并经项目作者审核，结果报告须标明这一题集来源及其限制。测试题不从已抽取的图边反向生成，以免偏向图谱方法。作者逐题核实答案与中英文证据，删除可仅凭标题猜出答案、证据不在双语语料中或边界模糊的题目。加入英文语料后须重新检查“不可回答题”的边界；不可回答题评估拒答准确率。

主指标：按必需证据组计算的证据 Recall@5；多跳题所有必需证据组在 Top-5 中均被命中的比例；人工按统一准则标注的答案正确/部分正确/错误与引用是否支持论断。中英文片段只有人工确认可支持同一论点时才放入同一组，不能按翻译相似度自动合并。两周版对全部 60 道封存题的三个方法输出做人工盲评；第一周仅对 12 道开发题做功能性初评，不作为最终效果结论。逐题记录证据语言、原文路径、延迟、token 与费用，并可按证据语言拆分结果。辅助：RAGAS faithfulness 可作趋势参考。生成模型、temperature、prompt、chunking、检索候选数、最终上下文 token 上限在所有方法中固定。抽样做错误归因：跨语言概念链接失败、图边错误、双语重复片段挤占、扩展噪声、排序问题、生成问题。

## 展示与交付

轻量 Python Web UI 设置“问答”和“知识图谱”两个独立页面，通过导航栏切换。问答页输入中文问题，并排展示纯向量与图增强答案；点击引用打开固定版本的中英文原文并显示证据语言，同时高亮本次检索使用的局部概念路径；提供预置多跳问题与失败案例。

知识图谱页默认展示当前本地图索引中的**全部活跃概念节点和关系边**，采用类似 Obsidian 图谱的可缩放、可拖拽交互布局；“全貌”仅指已抽取并保留的图，不代表教材全部知识。支持点击概念节点查看名称、直接相连的概念及关系，并按关系列出对应原文片段、语言、来源位置和固定版本链接；同一片段重复出现时合并展示。点击节点和浏览图谱均只读取本地图索引，不调用答案生成 API。页面须使用能把节点点击事件传回应用的可视化组件；具体组件在 Task 7 验证后确定。图中关系与抽取置信度不能替代原文证据，未逐条审核的边须有可辨认的状态提示。

项目 README 首屏展示问题、方法图、指标对比、消融、例子及失败分析，并附双语语料下载、校验、离线入库及复现实验命令。

### GitHub 公开仓库

项目代码和文档放在作者个人账号下的公开仓库。根目录提供 `README.md`、代码许可文件、`requirements`/锁定依赖、`.gitignore`、`.env.example`、中英文来源清单、下载脚本、最小自写双语示例语料、构建与评测命令、结果表和图。真实 API 密钥、`.env`、下载的教材 Markdown、本地缓存、向量和图索引、日志与可能含密钥的输出不提交。第一版公开仓库不直接打包第三方教材正文或其生成的全文索引；通过分别固定中英文仓库提交及文件哈希的下载/入库脚本复现，示例测试使用作者自写文本。正式发布前，从干净环境按 README 运行一遍下载、校验、入库、查询和评测；再检查 Git 历史与待推送文件是否含密钥或教材正文。为两个仓库的第三方语料分别标注来源、作者、对应版本的许可与再发布条件；代码许可不覆盖第三方文本。公开仓库的首屏展示实验结果和复现方式，避免只有截图没有可运行方法。

## 进度与范围控制

- 每天按 3–4 小时预算，第一周 21–28 小时，第二周同量。人工标注与核查预留约 10–12 小时，包含在总预算内；不默认有第二位标注者。
- 第 1–2 天：确定中英文文件清单与固定提交、完成本地下载和校验、统一文档结构、分块、题目标准与 12 道开发题；做双语向量基线。
- 第 3–4 天：抽取、消歧、来源校验及首批图边抽查；生成可用图。
- 第 5–6 天：实现无权一跳扩展和关系感知两跳重排；仅在开发题调参。
- 第 7 天：在开发题运行三种方法初评，验证中文问题召回英文证据、离线重建，以及增加一份自写 Markdown 后可重建索引和问答；交付可运行命令行或简易网页演示、首版开发集结果表，达到第一周最小版本。
- 第 8–9 天：补齐并封存到总计 72 题，完成 40 条图边抽查；固定参数后运行 60 题测试集并人工盲评。
- 第 10–11 天：完整对照、消融、按题型分析、错误案例与费用/延迟记录。
- 第 12–13 天：可演示 UI、README、结果图、录屏、公开仓库许可与密钥检查。
- 第 14 天：从干净环境复现实验，修复演示问题，把项目发布到作者的 GitHub 公开仓库，并打包面试材料。若进度延误，先保住证据链、实验公平性、可扩展入库与复现，再减少 UI 装饰。

两周版的范围上限：约 100–200 个概念、150–300 条关系、数百个原文片段。数字是预算，不是必须凑满的目标；图谱质量与评测可信度优先。第一周最小版本只要求覆盖 12 道开发题所涉及的概念与证据，以及能处理任意输入问题的完整流程。

## 约束与构建者自行决定的事项

用户确认：希望突出算法能力，1–2 周完成，每天 3–4 小时，有本地 GPU 和付费 API（例如 DeepSeek），选择图谱增强多跳检索；中英文教材 Markdown 均下载到本地，分片、索引、召回和重排在本地完成，大模型可以外接；中文问题可以引用英文原文。项目最终上传到自己账号下的 GitHub 公开仓库，知识库内容须能扩展。项目作者承担人工验证，不默认有第二位标注者。未指定 GPU 显存、API 支出上限、GitHub 仓库名或具体 Web 框架，实施者可在不改变对照公平性的前提下选择模型与工具。默认中文问答；语料范围、实验预算与本地 GPU 型号可在实施前按实际条件微调。正式发布时应检查当前 GitHub 工具是否已连接作者本人账号，并确认仓库所有者为作者本人。
